# Night run 2026-08-21 — time probes + five new-idea arms on the final configuration

All on the H100 Studio, minimum-bias, final configuration (W8 + recentre + Ex + Dn, qd, EMA),
single seed unless stated. Comparison scales: single-member 5-seed mean 0.0399 (sd 0.0005 over
seed means, per-member spread ~0.0010), seed-ensemble 0.0386 on this fixed split, full-CV

## 1. Interventional time probes (scripts/probe_time.py, reports/probe_time.csv)

Trained W8Rc member s0, inputs perturbed at evaluation, recalibrated per variant on the
perturbed validation split.

| variant | aggregate | reading |
|---|---|---|
| base | 0.0402 | sanity: matches the member's known score |
| time zeroed | 0.3099 | the no-time floor of THIS member (not retrained) |
| within-event permutation | 0.3975 | **worse than zeroed** |
| shift +0.5 sd (all cells) | 0.0577 | +44% |
| shift +1 sd | 0.1235 | |
| coarsen to 0.25 sd grid | 0.0445 | +11% |
| coarsen to 0.5 sd | 0.0479 | +19% |
| coarsen to 1 sd | 0.0949 | breaks |

Three answers the ablation could not give:

1. **The model reads per-cell time structure, not an event average.** Shuffling the timestamps
   among the cells of the same event (exact same multiset of values) is *more* destructive than
   deleting them. A model using only pooled time statistics would be permutation-invariant.
2. **It is not purely relative either.** A rigid shift of every timestamp in the event changes
   nothing pairwise, yet +0.5 sd already costs 44%. The model anchors on the absolute
   (median-subtracted) scale, where "in-time" means near zero — so a relative-time attention
   mechanism would discard an anchor the model demonstrably uses. Together with the ledger's
   geometric pairwise-bias arm (0.0420, lost), this closes the relative-time-attention idea
   with two independent measurements instead of an opinion.
3. **Useful precision ends between 0.25 and 0.5 sd of the timestamp spread.** Coarsening to a
   0.25 sd grid costs 11%, 0.5 sd costs 19%. This is the model-side answer to the
   timestamp-resolution question for Felipe: the network exploits time down to roughly a
   quarter of the per-event time spread, so the simulated resolution matters at that grain.

## 2. Five arms, one seed each

| arm | flag | sigma_eff | verdict |
|---|---|---|---|
| slot decomposition K=4 | --slots 4 | 0.0406 | neutral-to-lost; superposition structure does not move the floor |
| distillation from 5-seed teacher | --distill | 0.0397 | mild gain vs 0.0399 member mean; seeds 1-2 queued |

| D4 train-time augmentation | --d4aug | 0.0401 | neutral |

Notes.

- **--aux 0.0393**: auxiliary regression of the true photon entry (x, y) and time alongside the
  energy quantiles. Directionally the "learned recentring" hypothesis — teach the representation
  where the photon is, without touching the main path. One member below the 5-seed mean by
  0.0006 with per-member spread 0.0010: promising, not yet significant. Per-bin vs the
  5-seed ensemble everything is within errors.
- **--distill 0.0397**: even if the mean lands at ~0.0397, the point is deployment: near-ensemble
  accuracy at 1/5 the inference cost (single member 4,958/s CPU vs 111/s for the 5-ensemble).
- **d4 neutral is informative**: an 8-fold increase in geometric variety buys nothing while the
  measured scaling curve says 3x more *real* events buys ~0.006. What N^-0.18 purchases is
  diversity of pileup configurations, which symmetry transforms cannot manufacture. The "more
  data" request has no augmentation shortcut.
- Slot/time-gate/d4 join the closed-doors table; each was implemented because the error anatomy
  suggested it, and each answer is now measured rather than argued.

## 3. Rounds 2-4: the two candidates at five seeds

| | members (5 seeds) | seed-ensemble | paired bootstrap vs champion |
|---|---|---|---|
| champion (W8Rc) | 0.0399 +- 0.0005 | 0.0388 +- 0.0005 | — |
| + aux position head | 0.0393/0.0394/0.0395/0.0392/0.0400 = 0.0395 +- 0.0003 | 0.0382 +- 0.0005 | **-0.0005 +- 0.0003, P(better) 0.96** |
| + distillation | 0.0397/0.0394/0.0391/0.0397/0.0394 = 0.0395 +- 0.0002 | 0.0383 +- 0.0004 | **-0.0006 +- 0.0003, P(better) 0.98** |

Same fixed split, same protocol, per-event median across seeds, 400 paired resamples. Both
gains are small (~1.5%) but systematic: consistent at member level (5/5 and 4/5 seeds below
the champion member mean) and at ensemble level. The aux gain supports the learned-recentring
reading: telling the representation where the photon truly is helps, without touching the
readout path. Distillation additionally halves nothing about training but matters for
deployment: a distilled single member at 0.0395 runs 5x faster than the 0.0388 ensemble.
The combined arm (--aux --distill, 3 seeds: 0.0397/0.0395/0.0391, 3-seed ensemble 0.0387,
paired -0.0002 +- 0.0003, P 0.65) does NOT stack: members land exactly where each single
lever lands. The two levers apparently buy the same margin — both pull the single member
toward the ensemble's average behaviour, one through a truth-position side task and one
through the teacher directly — so the paper should present them as two routes to the same
~0.0005, not as additive improvements. Studio stopped after this run.

## 4. Round 5 (daytime): the SOTA push

- **New best: aux 10-seed ensemble 0.0380 +- 0.0005** — paired vs the 5-seed champion
  -0.0008 +- 0.0003, P(better) = 1.00 (wins in 400/400 paired resamples). First fully
  significant architecture-side gain of the project.
- **Quality-cut path is dead, by construction.** sigma_eff-vs-efficiency with the predicted
  interquartile width (threshold per region x val-energy-decile, fitted on validation):
  cutting to 80% efficiency makes sigma_eff WORSE (0.0383 -> 0.0412). The reason is the
  metric itself: sigma_eff is the minimal 68.3% interval, a robust statistic — the
  catastrophic tails the width flags (AUC 0.93) already sit OUTSIDE the interval, so removing
  them cannot shrink it. The oracle -30% from residual-trimming trims bulk-edge events the
  width cannot identify. Quality flags still matter for physics (tail purity for analyses)
  but cannot buy quoted resolution. reports/width_efficiency.csv.
- **Oracle-centre run prices centring at -4% aggregate** (single member 0.0383 vs 0.0399;
  15mm low 0.0713, 30mm low 0.0687 — about -10% in the weak bins). The largest measured
  remaining in-data lever.
- **The aux head localises the photon 3x better than the current window centre**: median
  position error 0.33-0.43 of the predict-nothing baseline in every region
  (reports/predictions/auxpos_test.npy). Together with the oracle bound this motivates the
  next build: two-stage learned recentring — first pass predicts the photon position, the
  window is re-cut around it, second pass regresses the energy. Expected capture: a large
  fraction of the oracle's -4%/-10%, on top of 0.0380.
- Per-cell information ceiling at W8 (overlay): the observables-fitted gate reaches
  corr 0.93-0.95 with truth and sits within 10-12% of the ORACLE gate readout — the per-cell
  separation information is nearly exhausted by observables; what remains after oracle is
  invisible to the detector, not to the model.

## 5. Incident: silent 4-file dataset

The first launch of tonight's queue ran probes, teacher and the first arm on **3,173 events
instead of 72,554** with no error raised: the GPU-benchmark fix earlier this week had deleted
the 0-byte stub files in `data/minimum_bias/`, leaving 4 real files, and `cached_grid`'s cache
key is `minbias_{n_files}` — so it silently built and cached `minbias_4.pkl` instead of hitting
`minbias_94.pkl`. Caught because the farm's first score (0.0353 "aggregate" on 476 test events)
was implausibly good. Fixed by restoring the stub count, deleting the contaminated checkpoint,
and relaunching; every number above is from the full-cache rerun. Lesson recorded: the cache key
counts files, it does not checksum them.
