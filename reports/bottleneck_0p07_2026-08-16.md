## 3. What timing can and cannot do

Measured on the paired overlay sample with a reference time estimated from the seed cells only
(no truth), pileup is far broader in time than the photon: energy-weighted rms 13.2 ns against
1.6 ns at 15mm, 8.5 against 0.9 at 30mm. So a large out-of-time component exists and is removable
-- which is a different question from in-time rejection, where sigma_t/Delta_t > 1 closes the door.

Cutting on the per-cell time pull |t - t_ref| / sigma_t(E), at 15mm:

| pull cut | photon kept | pileup kept | naive sigma gain |
|---|---|---|---|
| < 5 | 0.968 | 0.543 | 1.36x |
| < 3 | 0.945 | 0.410 | 1.56x |
| < 2 | 0.908 | 0.310 | 1.80x |
| < 1.5 | 0.857 | 0.249 | 2.01x |
| < 1 | 0.722 | 0.173 | 2.40x |

Timing is worth about **2x** before photon loss costs more than the pileup it removes -- against
the 6.1x needed. And as a *hard cut* it is actually harmful: applied alone it moves 15mm low-E
from 0.6155 to 0.5296 on the overlay sample but the full-sample number gets worse (0.3513 ->
0.3742), because discarding 5% of the photon adds containment fluctuation. Timing has to enter as
a soft weight, which is what the gate is for.

## 4. The decisive measurement: the information is there and the model is not using it

`cell_info_ceiling.py` fits a per-cell gradient-boosted regressor on the paired sample to predict
each cell's photon fraction from **observables only** (log energy, time pull, ring distance,
front/back asymmetry, energy share, window totals), then uses its output as the gate in the same
weighted-sum readout. Fitted and scored on disjoint events:

| region | estimator | sigma_eff | low-E |
|---|---|---|---|
| 15mm | raw sum | 0.3513 | 0.6155 |
| 15mm | time-pull cut < 3 | 0.3742 | 0.5296 |
| 15mm | **gate from observables** | **0.2078** | **0.2906** |
| 15mm | oracle gate (truth) | 0.1862 | 0.1869 |
| 30mm | raw sum | 0.3230 | 0.6435 |
| 30mm | **gate from observables** | **0.1348** | **0.2170** |
| 30mm | oracle gate (truth) | 0.1185 | 0.1113 |

Per-cell correlation with truth: **0.930 at 15mm, 0.949 at 30mm — against 0.211 for the trained
network's emergent gate.** A 200-tree model on eight hand-made features extracts in seconds most
of what the oracle knows; the network extracts almost none of it. The feature gate recovers about
64% of the oracle's gain over the raw sum at 15mm low-E.

This reverses the conclusion I reached earlier today. Gate supervision failing does **not** mean
the ceiling is informational. It means the supervision as implemented did not transfer: it was
applied only to overlay events through the `HASF` mask, so the gate on real min-bias events was
never touched and stayed at 0.211.

(Note the overlay sample is harder than real min-bias -- 54% of window energy is pileup at 15mm
versus roughly 30% in real data -- so absolute values here are not comparable to the champion's
0.1697. The ratios are what transfer.)

## 5. Option space, ranked by evidence

**A. Feed the per-cell fraction estimate to the network as an input feature.** The GBM output is
computable at inference from observables alone -- no truth needed -- so a frozen per-cell
pre-processor is legitimate. Highest expected value by a wide margin: it converts a measured
0.93-correlation signal the network currently ignores into an input it cannot ignore.
*Known obstacle:* the synthetic-to-real domain gap. H3 in the novelty ledger already recorded
overlay fraction labels failing with a domain-gap AUC of 0.74. That is the thing to attack, and
it is now worth attacking because the payoff is quantified.

**B. Make the emergent gate learn what the GBM learns.** The eight GBM features are all
derivable from inputs the network already has, so the gap is architectural or optimisation, not
informational. Candidates: give the gate its own head with the time pull as an explicit input
rather than a raw timestamp; check whether the readout's `log1p` saturation flattens the gate
gradient at low photon fraction; supervise on real events using the GBM output as a soft teacher
instead of synthetic truth, which sidesteps the domain gap entirely.

**C. Loss weighting on the sparse slices (`--wlow`).** 103 events/seed in the worst slice with a
+0.197 median bias. Coded, never taken past screening. Cheap, independent of A and B.

**D. Outside-window pileup density subtraction (`--orho`).** Coded, incomplete at 5 seeds. Now
clearly motivated since pileup is the whole gap; the outside-window density matched the
inside-window density to 1% at 15mm and 30mm.

**E. Front+back inverse-variance time combination.** Expected 0.82x on per-cell sigma_t, which
tightens every pull cut in section 3. Small but compounding with A and B.

**F. A dedicated low-E expert.** One shared model spends capacity on abundant easy events. The
`--film` conditioning machinery already exists. Structural version of C; do it only if C helps.

### Ruled out by measurement, do not spend GPU

- **Per-cell gate supervision as implemented** (`--gatesup`): three arms, net effect under 2x its
  error, and the synthetic data hurts on its own (`gatesup_2026-08-16.md`).
- **Hard timing cuts**: worse than no cut (section 3).
- **Post-hoc calibration**: sigma_eff is a minimum-width interval, location-invariant, so removing
  the +0.197 bias cannot move it.
- **Ensembling**: epistemic/aleatoric ratio 0.21-0.27 caps it near 3% against the 74% needed.

## 6. Honest target statement

0.07 in all fifteen bins is consistent with the detector: every failing slice has clean-sample
headroom. It requires removing 91-97% of pileup variance, and the largest identified lever -- the
per-cell fraction information the network is currently discarding -- is measured, not speculative.
Nothing yet demonstrates that removal on real data, so the credible near-term milestone remains
15mm low-E 0.17 -> 0.11-0.13 and 30mm low-E 0.10 -> 0.08, with 0.07 as the target the option
space above is now aimed at rather than a number the physics forbids.
